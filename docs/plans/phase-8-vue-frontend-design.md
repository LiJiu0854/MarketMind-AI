# 单元 8：Vue 企业运营工作台设计

**状态：** 用户已审阅并批准本设计；实施计划仍需单独审阅。本文不是开始编码的许可。

## 1. 目标、用户和成功标准

MarketMind AI 已有认证、商品、知识库、语义审核、受控研究及人工审批交付的后端闭环，但团队目前只能直接调用 API。单元 8 的目标是把这条闭环做成整洁、大方、可实际使用的中文企业运营工作台，而不是展示假数据的 Demo。Admin、Operator、Analyst 应能在各自权限内完成从资料准备、商品运营到研究交付的实际操作，并看懂任务状态、失败原因和证据来源。

用户明确要求保持学习优先、成品可写入简历、四个 Task、每个 Task 一份本地中文学习文档。文档应按真实开发顺序解释新增代码为什么写、每行或每组重复代码的作用、调用的是项目代码还是已有包、数据如何流动、功能的实现原理、测试失败到通过的过程，以及如何迁移到相近问题。工程代码和设计/计划文档可提交；`docs/learning/` 下既有及新建教程和用户练习测试只保留本地，不暂存或提交。

完成标准是：三个角色的授权操作真实调用现有 API；商品、知识库、审核与研究能从界面进入并完成；异步状态和证据可追溯；错误可恢复且不泄露敏感信息；桌面与窄屏可用；前端测试、类型检查、构建和人工视觉检查通过。真实模型/向量服务未配置时，界面应诚实显示服务不可用，不能伪造成功结果。

## 2. 方案选择与边界

| 方案 | 收益 | 代价与结论 |
|---|---|---|
| **Vue 3 + Vite + TypeScript + Vue Router 的独立 SPA** | 与当前 FastAPI API 契合、页面边界清晰、适合逐 Task 学习，可直接定制视觉 | 需要维护小型前端工程；采用 |
| 大型 UI 组件库驱动的 SPA | 表单和表格可以更快起步 | 样式同质化、依赖和学习面增加；本单元不采用 |
| Nuxt/SSR | 适合公开内容的服务端渲染需求 | 当前是登录后工作台，没有 SEO/SSR 目标；不采用 |

前端仅消费已经存在的 `/api/v1` 契约，不新增后端业务接口、数据库表、租户体系、外部企业系统连接、实时推送或伪造的统计 API。初始 Admin 仍通过已有 CLI 创建；Chat/Embedding 模型切换继续使用后端的 `LLM_*`、`EMBEDDING_*` 配置，前端绝不接收供应商密钥。单元 9 才负责正式同源反向代理、CI、部署和系统级端到端流水线；单元 8 仍须有足够的本地自动化与人工验收。前端使用原生 `fetch`、`FormData`、`Blob`、CSS 和浏览器能力，不引入 Axios、Pinia、图表库、UI 框架或图标包，除非实施中出现明确且可验证的不足。

## 3. 工程架构和数据边界

在仓库根目录新增 `frontend/`，承载 Vue 单文件组件、TypeScript 类型、路由、API 客户端、少量复用组件、设计变量和测试。Vite 开发代理把相对路径 `/api/v1/*` 转发到本地 FastAPI `8010` 端口；前端不内置服务密钥或数据库连接。正式环境仍使用相同的相对路径，由单元 9 的同源部署处理，避免在业务组件里散落环境 URL 或依赖宽泛 CORS。

数据流为“页面/表单 → 类型化 API 函数 → 统一请求层 → FastAPI → MySQL/Redis/Celery/Chroma”，响应按相反方向返回。API 层只做认证头、JSON/FormData/文件响应、统一错误解码；页面负责业务交互和局部状态，不建立一个复制后端数据的全局 Store。Vue Router 负责 URL 和受保护页面；共享登录状态只包含当前 Token 与 `/auth/me` 校验出的用户。需要刷新数据时重新请求后端，MySQL 仍是业务真相。

登录调用现有 `POST /api/v1/auth/token` 的表单格式，成功后核验 `/auth/me`。30 分钟 Access Token 保存在当前标签页 `sessionStorage`，刷新后重新核验；退出或任何受保护请求返回 `401` 时清除凭证并回到登录页。该存储方式改善刷新体验，但脚本可访问 Token：因此不使用 `v-html` 展示商品、文档、模型或报告文本，不把 Token 放在 URL、日志或错误文案中；未来若后端提供 HttpOnly Cookie/刷新机制，再整体迁移认证边界。`403` 不应被误判为登出。

## 4. 页面、角色与组件职责

所有登录后页面共用工作台外壳：侧栏导航、顶部当前页/账号信息、主内容区、通知与确认交互。小屏将侧栏折叠，表格保持可读的横向滚动；页面优先清楚展示“当前对象、当前状态、下一步操作”，不堆砌仪表盘。首页只呈现真实可用入口和从现有接口取得的内容，不制造“节省多少小时”等无法核验的指标。

| 页面或能力 | Admin | Operator | Analyst | 主要 API 与行为 |
|---|---|---|---|---|
| 登录与工作台 | 使用 | 使用 | 使用 | `/auth/token`、`/auth/me`；按角色显示入口 |
| 用户管理 | 创建/编辑/停用 | 无入口 | 无入口 | `/users`；创建请求携带 `Idempotency-Key` |
| 商品列表/详情 | 读写、导入/导出 | 读写、导入/导出 | 只读、检查/导出 | `/products`、`/import`、`/export`、`/listing-check` |
| 语义审核 | 发起/查看 | 发起/查看 | 查看 | 商品下 `/semantic-reviews`；结果与快照分开展示 |
| 知识库 | 创建、上传、提问/查看 | 提问/查看 | 提问/查看 | `/knowledge-bases`、`/documents`、`/questions` |
| 受控研究 | 发起/查看 | 发起/查看 | 查看 | 商品下 `/research-runs`；来源、步骤、报告和用量可见 |
| 报告审核与交付 | 审核/下载 | 下载已批准报告 | 下载已批准报告 | `/review`、`/export`；不可审核与未批准状态不显示为可交付 |

导航只呈现角色可使用的页面，操作按钮按角色及当前业务状态启用；这仅是易用性措施，所有请求仍由后端 JWT/RBAC 和业务约束最终裁决。对有破坏性或不可逆的动作（停用用户/商品、研究批准或驳回）提供明确确认，说明后果；审核 UI 不暗示可以撤销。研究详情必须同时呈现发现/建议与其 `source_id`、已登记文件名/页码/摘录；证据不足时直观显示“不可审核”，不能把模型文字排版成已证实结论。

可复用单元限于确有复用价值的工作台外壳、API 请求层、状态标签、分页/空状态、表单反馈与确认交互；商品、知识库、研究保留各自页面组件，不预建通用 CRUD 生成器或配置驱动的工作流引擎。

## 5. 关键交互与异步状态

商品列表直接使用后端的分页与 `sku/brand/category/is_active` 筛选语义；导出复用当前筛选参数，不在前端另造不同结果。创建/编辑表单与后端字段匹配，价格作为十进制文本提交，不用浮点计算；卖点按可增删的逐条输入收集。导入只接受 `.xlsx`，展示总行数、成功/失败数和逐行错误；文件类型和大小可提前提示，服务端校验仍是权威。商品或研究 Excel 下载经带 Bearer Token 的请求获取 `Blob`，触发下载后撤销临时 URL，不把 Token 拼进链接。

文档上传使用 `FormData`；语义审核、文档索引和研究创建收到 `202` 后，进入相应详情并读取 MySQL 历史/详情中的 `pending/running/success/failure` 或文档 `ready`。仅在相关页面可见且任务未终结时按有界间隔轮询；终态、离开页面或组件销毁立即停止，不无限重试，也不把 Celery Result Backend 当业务状态。知识库提问使用现有同步问答接口，显示真实引用或拒答；不把它误设计成异步轮询。

管理员提交研究审核前，页面依据 `review_status` 显示资格和一次性决定的说明；后端仍重新校验完整研究和证据。驳回必须有意见；提交后重新获取研究详情，展示不可变审核人、时间和意见。未批准报告不提供下载按钮；即使直接调用导出 API，后端仍会拒绝。用户创建的 `Idempotency-Key` 按一次逻辑提交生成，网络超时后对**同一输入**重试时复用，输入变化则生成新键，避免重复创建或错误复用。

## 6. 视觉、可用性与可访问性

整体采用克制的企业运营视觉：浅暖色画布、深色正文、青绿色主操作、低饱和的警告/失败色；侧栏与内容区形成稳定层级。建立少量 CSS 变量统一颜色、字阶、间距、圆角和阴影，避免每页临时拼样式。表格重视信息密度但留足行高，长文本可展开；状态使用文字加颜色，不能仅靠颜色区分。重要按钮与下一步操作在视线主路径上，危险操作使用次要位置和二次确认。动画仅辅助状态过渡，遵循减少动态效果偏好。

每页有加载、空数据、无权限、失败和成功反馈；表单使用可见标签、说明与就近错误，键盘可完成主要操作，焦点可见，弹层可关闭并恢复焦点，颜色对比度和窄屏阅读性纳入人工验收。人工检查至少覆盖约 1440、1024、390 像素宽度；窄屏不要求所有表格列同时出现，但不得遮住主要操作或造成不可恢复的横向页面溢出。真实截图/界面检查用于验证“好看、整洁、大方”，自动化测试不能替代视觉验收。

## 7. 错误、安全和失败恢复

后端业务错误稳定返回 `code/message/request_id`；请求层解析这些字段，解析失败时给出安全的通用提示，不在页面展示堆栈或原始响应。`401` 清除登录态；`403` 解释权限或账号状态但不清除有效凭证；`409` 提示冲突并提供重新读取入口；`422` 提示修正输入（后端当前不提供字段级详情，前端只做必要的即时约束提示）；`429` 展示限流/稍后再试；`503` 与网络失败区分服务暂不可用。请求 ID 可供排查，但 Token、密码、上传文档内容和完整模型原始响应不写入前端日志。

创建、审批、导入等写操作在请求中禁用重复提交；网络超时不自动重放。异步任务失败展示后端允许公开的错误码/摘要和可行下一步，不假装继续成功。列表请求使用请求取消或结果序号，避免快速切换筛选时旧响应覆盖新结果。错误展示不覆盖仍可阅读的旧数据；用户可以明确重试只读请求。客户端校验改善体验，不代替后端校验与权限。

## 8. 四个 Task、测试和验收

1. **Task 1：前端基础与账号。** 建立 Vue/Vite/TypeScript/Router、设计变量、工作台外壳、请求层、登录恢复/退出和 Admin 用户管理；验证凭证、`401/403`、角色导航、用户创建幂等键。
2. **Task 2：商品运营。** 实现分页筛选、创建/编辑/停用、Listing 检查、`.xlsx` 导入错误报告和当前筛选导出；验证 Decimal 文本、权限、下载、重复提交和空/失败状态。
3. **Task 3：知识库与语义审核。** 实现知识库创建、上传、索引状态、问答引用和历史，以及商品语义审核发起/结果；验证上传边界、拒答、终态轮询和模型不可用反馈。
4. **Task 4：受控研究与交付。** 实现研究发起、进度、证据/报告、Admin 一次性审批和已批准 Excel 下载；完成三角色回归、窄屏/键盘/视觉验收、README 与四份中文教程。

每个 Task 按 RED → 最小 GREEN → 重构实施。前端采用 Vitest、Vue Test Utils 对请求层和关键交互做确定性测试，模拟 `fetch` 而不调用真实付费模型；执行 TypeScript/Vue 类型检查和生产构建。测试至少覆盖登录过期、角色边界、分页/筛选与导出一致性、导入错误、文件上传、异步轮询停止、证据不足、审核冲突及受控下载。单元末运行既有后端工程检查，说明用户本地练习测试的已知失败与本单元回归的区别。人工验收用三类账号验证端到端业务流程及视觉/可访问性；真实模型调用仍须单独明确配置与费用，不由自动化测试触发。

## 9. 交付约束和后续单元

单元 8 交付可在本地实际运行的前端、锁定依赖版本的包管理文件、运行说明、必要测试和四份仅本地保留的中文教程。新建的 `frontend/node_modules/`、构建产物和本地环境文件须加入忽略规则。提交只暂存精确工程文件，保护现有 `docs/learning/` 与 `tests/unit/models/test_product_practice.py`。不读取或输出 `.env` 中的秘密，不擅自推送、合并或删除阶段分支。

若正式环境需要跨域认证、HttpOnly Cookie、用户级审计、实时通知或外部企业系统同步，应在明确需求与后端契约后单独设计，不在本单元猜测实现。单元 9 处理 CI、部署、正式同源路由及系统级端到端验收；本单元的本地构建和测试不能被推迟到单元 9。
